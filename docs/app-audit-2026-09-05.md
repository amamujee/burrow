# App audit · September 5, 2026

Audit against `93cbf69`. Modules A–D were approved for release on September 5, 2026. The larger decisions below remain proposals.

The strongest improvements are correcting accidental answer giveaways and removing repeated generation work. The existing game modes, layouts, topic catalog, real imagery, tap targets, and learning flow remain intact. No packages, settings, or modes were added.

## Difficulty evidence

Hard's depth mix changes from 10% Easy / 30% Medium / 60% Hard to 8% / 20% / 72%. Retrieval questions are distributed throughout the seed cycle. The full card catalog stays available. Actual session proportions also reflect learning-history selection.

Across the same 1,000 multiplication seeds, mean product increased from 81.273 to 96.763: **19.06%**. Factors reach 16 × 16. Contextual counts reach 30. Hard Sort keeps four cards, with a rotating candidate window reduced from 80% to 64% of the ordered pool. Top Trumps uses the same narrower window among comparable opponents. Hard building-difference distractor spacing falls from 75 ft to 60 ft.

Easy and Medium generator outputs matched baseline hashes across all six built-in topics and loaded packs. Fixed Challenge campaigns and Math Trail have no difficulty selector, so their content is preserved. Peek reveal timing and geographic pin separation are preserved.

These are measurable calibration changes, not a claim that every question or child's error rate changes by exactly 20%. Removing answer giveaways will also affect perceived difficulty.

## Correctness findings

- Subtraction photo badges displayed the answer before submission. Building-height and pepper-SHU recall questions exposed the same answer-bearing information.
- Subtraction photos accepted card-name answers even though the valid choices were numeric. The original production build failed the new regression because these illustrations were rendered as answer buttons.
- In pack comparisons, photo taps bypassed the first-wrong-answer clue used by the answer buttons. Both now share one path, and a rejected photo cannot be submitted repeatedly.
- Peek promised a map after answering, although that feedback map was intentionally absent.

## Performance evidence

Warm local Node generator timings:

| Operation | Before | After |
| --- | ---: | ---: |
| Mixed Hard Geo round | 127.9 ms | 0.3 ms |
| Mixed Hard Quiz session | 127.7 ms | 46.5 ms |
| Pepper Hard Quiz session | 348.8 ms | 88.0 ms |

The speed changes produced byte-for-byte identical JSON in 112 Geo round comparisons and 144 complete Quiz sessions containing 2,304 questions, including 382 location questions. Tests cover first-candidate failure, US map preference, and seeded output preservation.

Production Chrome measurements used the same 1024 × 768 touch viewport, 2× pixel density, 4× CPU throttling, blocked service workers, and five navigations per build. Medians:

| Browser operation | Before | After |
| --- | ---: | ---: |
| Navigation to saved-profile/game readiness | 1,578 ms | 929 ms |
| Startup main-thread blocking beyond 50 ms per task | 1,395 ms | 740 ms |
| Select Hard → new round ready | 1,216 ms | 413 ms |

This is about **41% less startup waiting** and **66% less waiting after selecting Hard** in the local simulation. Immediate input feedback remains within a frame; ordinary Skip timings did not show a clear improvement. These measurements are from a simulated tablet on the local machine, not a physical iPad or a production network. Raw measurements are retained in `.burrow/baseline-benchmark.json`, `.burrow/updated-benchmark.json`, and `.burrow/audit-geography-performance.json`.

## Decisions reserved for approval

1. **Respect a manually chosen difficulty.** The existing automatic rules can lower manually selected Hard based on lifetime accuracy. A manual-versus-automatic distinction would make this preference stick, but changes progression semantics and saved state.
2. **Treat Top Trumps ties consistently.** Ties preserve streak and receive neutral feedback, but the current progress totals count them within `answered - correct`, labeled Incorrect. Track ties explicitly and exclude them from accuracy, with a compatibility plan for existing progress.
3. **Adjust Hard multiplication help.** Worked strategies can expose substantial help before submission. Delaying the worked solution while retaining the visual groups could make Hard more demanding, but changes teaching behavior and deserves a deliberate choice.

Further startup splitting and offline image warmup are lower-priority follow-ups. The current changes address measured waste without introducing a larger loading architecture.
